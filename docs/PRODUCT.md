# Product Contract

## Experience target

Preserve Hermes Desktop's identity and agent transparency while adapting the interaction model to Android. The app must feel like Hermes, not like a generic chat client.

## Primary surfaces

- Home: gateway health, active work, recent sessions, pending approvals.
- Chat: streaming conversation, composer, tools, attachments, voice, and recovery.
- Activity: agent run timeline, tools, sub-agents, approvals, failures, and artifacts.
- Sessions: search, resume, branch, usage, and history.
- NOUS: search, capture, review, project context, and vault health.
- Automations: bounded schedules, run status, logs, and delivery state.
- Settings: gateways, security, appearance, notifications, diagnostics, and data controls.

## Mobile adaptation rules

- One-handed primary actions.
- Bottom sheets for previews and contextual details.
- Full-screen destinations for code, diffs, and long tool output.
- Navigation rail and two-pane layouts for tablets and foldables.
- No compressed desktop sidebar on phone.
- Remote execution location is always visible.

## Quality bar

No screen is complete with only a happy path. Every screen needs intentional states, motion, accessibility semantics, touch-sized controls, and real-device verification.
